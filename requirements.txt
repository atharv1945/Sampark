# SAMPARK — Python dependencies
#
# Python 3.11.9 only. Install into a local .venv:
#   py -3.11 -m venv .venv
#   .venv\Scripts\python.exe -m pip install -r requirements.txt
#
# Phase 0 scope: this file deliberately contains ONLY what the CI job and the
# Phase 0 test suite require, plus Pydantic — required starting with the
# domain/API contracts implementation (CONTRACTS.md) — and the Razorpay SDK,
# required for the Phase 0 test-mode payment-link exit criterion.
#
# Phase 1 scope (data spine, spec §7/§18.1): NumPy/Pandas for the seeded
# simulator; PyYAML for the versioned root-cause lookup table
# (sampark/rootcause/taxonomy.yaml); psycopg to load the generated ledger
# into the real PostgreSQL 16 instance (docker-compose.yml, schema applied
# separately).
#
# Phase 3 scope (Agent Registry, spec §8.1): PyNaCl for Ed25519 keypair
# generation and detached-signature verification (sampark/registry/keys.py,
# signing.py) — chosen over `cryptography` as the smaller, purpose-built
# dependency (bundled libsodium wheels, no OpenSSL/X.509 stack this
# project has no other use for). FastAPI, redis, structlog still arrive in
# the phase that first uses them, not before.
#
# Phase 6 scope (intelligence layer, spec §7/§18.1): scikit-learn, for
# `sklearn.isotonic.IsotonicRegression` (sampark/models/calibration.py) —
# the ONE calibration method the spec names. No LightGBM: every Phase 6
# model this repository actually fits is a tabular lookup-table model
# (sampark/models/uplift.py, fatigue_hazard.py), matching
# sampark/allocator/calibrated.py's existing precedent; a gradient-boosting
# dependency with nothing in the repo that trains one would be exactly the
# "unnecessary dependency" CLAUDE.md §6 warns against.
#
# Pins are exact for reproducibility, verified against `pip freeze` after
# the first real install into .venv (Python 3.11.9).
# ---------------------------------------------------------------------------

Run the test

operator control
  1. 1  Open a session

    Creates a throwaway PostgreSQL schema and registers payment_retry_agent. The protected audit chain is never written to.

  2. 2  Create the ₹1,000 payment

    A real Razorpay Test Mode payment link. SMS and email notifications are switched off — this demo never contacts a real person.

  3. 3  Create the contrast payment

    A second real test payment, above the economic bar. This is what makes the contrast visible.

  4. 4  Make them fail

    Open each checkout and pay with a Razorpay test card that fails. Nothing here simulates the failure — Razorpay produces it and SAMPARK reads the real error code back. Test card reference ↗

  5. 5  Let SAMPARK decide

    Reads each failed payment back from Razorpay, normalises it into a risk item, and runs the unmodified decision path.

  6. 6  Prove it

    Recomputes every hash and checks the linkage.

Arms the mock channel so the next send fails. The grant rolls back, budget and contact slot are released, and no double-send occurs.
